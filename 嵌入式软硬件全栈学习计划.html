01

毕业时你应该能做到

这三条线同时长，缺一条都不算"吃透"

硬件线 HARDWARE

  • 拿到一块陌生板子，30 分钟内看懂它的电源、时钟、复位、接口布局
  • 看数据手册能算出该用多大的限流电阻、去耦电容、上拉阻值
  • 用嘉立创 EDA 独立完成原理图 → PCB → 打样 → 手焊 → 点亮
  • 用万用表 / 逻辑分析仪 / 示波器定位"代码没问题但硬件不工作"
  • 能判断一个电路方案在成本、功耗、可靠性上的取舍

软件线 SOFTWARE

  • 裸机：从启动文件到中断向量表，能自己配时钟、外设、DMA
  • RTOS：多任务划分、优先级设计、任务间通信，能讲清每一处为什么
  • Linux：写应用、写驱动、看懂设备树，能定位内核 oops
  • 协议：自己设计帧格式、CRC、超时重传，而不是照抄别人的
  • 调试：HardFault 十分钟内定位到行号，不靠"改改试试"

工程线 ENGINEERING

  • 分层架构：驱动层 / 业务层 / 应用层边界清晰，换芯片只改驱动
  • 版本管理：Git 分支、提交规范、可回溯的每一次改动
  • 构建：手写 Makefile、链接脚本、交叉编译，不依赖 IDE 魔法
  • 文档：原理图、BOM、接口文档、测试记录、复盘报告齐全
  • 交付：能在一个陌生环境里复现自己的项目
02

四条学习方法

方法不对，时间翻倍也没用

先跑通，再搞懂任何新外设：先让 demo 出结果（看到波形/灯亮），再回头读手册问"为什么"。反过来容易卡死。
改着做，不是照着抄看教程跑通后，必须自己改三个地方：换个引脚、加个功能、故意弄坏看报错。能改才算会。
用输出倒逼输入每个模块结束写一页笔记：这个外设的原理、我踩的坑、下次怎么避免。写不出来就是没学会。
每周留一次"无教程时间"关掉所有视频，只留数据手册，独立完成一个功能。这是从学生变成工程师的关键动作。

这四条讲的是"手怎么动"。理论怎么配、怎么和实践咬合——第二轮起改成先写预测再动手——见 学练双线。

03

14 个学习模块

前 11 个按顺序推进，最后两块是方向选择

M1

电路与电子基础

40 h

目标：看懂任何一块开发板的原理图，知道每个元件为什么在那儿。

硬件

  • 欧姆定律、分压、限流
  • 二极管 / 三极管 / MOSFET 开关
  • 电容去耦、RC 时间常数
  • 上拉下拉、推挽开漏
  • LDO 与 DCDC 的区别
  • 晶振、复位、BOOT 电路
  • 用万用表实测验证

软件

  • 建立"代码 → 引脚 → 电压"的映射直觉
  • 用逻辑分析仪看电平跳变
  • 这一阶段不写复杂代码
验收：不看教程，讲清开发板原理图每一部分的作用；用面包板搭一个 MOSFET 低边开关，实测电流与温升。
M2

C 语言与嵌入式编程

40 h

目标：写得出不靠库、能被别人看懂的嵌入式 C。

核心

  • 指针、数组、函数指针
  • 结构体与内存对齐
  • const / volatile / static / extern
  • 位操作与位域
  • 宏、条件编译、头文件组织

进阶

  • 栈 / 堆 / .data / .bss 布局
  • 环形缓冲区
  • 状态机（switch / 表驱动）
  • 回调函数与解耦
  • 编码规范（简化版 MISRA）
验收：手写环形缓冲、状态机、单链表，不查资料；画出自己程序的完整内存布局图。
M3

MCU 外设与底层驱动

120 h

目标：不查教程，从寄存器层面把一个外设配明白。

基础

  • 启动流程与中断向量表
  • 时钟树与分频
  • GPIO 八种模式
  • NVIC 优先级与临界区
  • 看门狗

核心外设

  • 定时器：PWM / 输入捕获 / 编码器
  • ADC：采样时间 / DMA / 注入
  • UART：DMA + 环形缓冲 + 协议帧
  • I2C：时序 / 上拉 / 时钟拉伸
  • SPI：四种模式 / DMA
  • DMA 通道与地址对齐
  • 低功耗模式与唤醒
验收：六个外设各有 demo + 逻辑分析仪波形截图；自己设计一个带帧头、长度、命令、CRC 的串口协议并实现对端解析。
M4

调试与故障定位

30 h

目标：出问题时不再靠"改改试试"，而是能定位到根因。

能力

  • HardFault 异常栈回溯，从 LR / PC 找到出错行
  • GDB + OpenOCD：断点、观察点、内存查看、单步汇编
  • printf 重定向、SWO / ITM 输出
  • 常见故障库：时钟没使能、引脚复用冲突、栈溢出、中断优先级、DMA 对齐、上电时序
  • 用逻辑分析仪判断"是硬件还是软件"
验收：故意制造 8 种典型 bug，每种都用工具定位到具体行号，并写下排查路径。
M5

硬件设计与打板

60 h

目标：从零画一块能工作的板子，这是硬件能力的硬门槛。

设计

  • 嘉立创 EDA / KiCad 基本操作
  • 原理图 → 封装 → PCB
  • 电源设计：LDO 选型、输入保护
  • 去耦电容布置
  • 晶振与地平面
  • 走线宽度与载流

制造

  • Gerber 与 DFM 检查
  • 嘉立创打样流程
  • 手焊 0603 / QFP
  • 热风枪拆焊 QFN
  • 上电前检查与限流上电
验收：独立画出并打样一块最小系统板（MCU + 电源 + 下载口 + 至少一个外设），焊接后能烧录运行。
M6

RTOS 实时系统

60 h

目标：把裸机的 while(1) 重构为可维护的多任务系统。

能力

  • 任务、调度、优先级、时间片
  • 信号量 / 互斥量 / 队列 / 事件组 / 任务通知
  • 优先级反转与优先级继承，死锁的四个条件
  • 栈大小估算与溢出检测
  • ISR 与内核交互原则（ISR 里只做最短的事）
  • 内存管理与静态分配优先
验收：做采集 + 显示 + 通信三任务系统，讲清每个任务优先级与栈大小的依据；现场复现一次优先级反转并演示修复。
M7

工程化与通信协议

40 h

目标：代码能给别人接手，项目能复现、能交付。

工程

  • 分层架构：HAL / 驱动 / 业务 / 应用
  • 手写 Makefile、CMake
  • 链接脚本 .ld 与内存段
  • Git 分支模型与提交规范
  • 代码评审清单

协议

  • 帧结构设计（帧头/长度/命令/CRC）
  • 超时重传与流控
  • Modbus RTU
  • CAN 帧格式与仲裁
  • 协议状态机实现
验收：把前面所有 demo 重构进一个分层工程，写接口文档；别人按文档能在 30 分钟内跑起来。
M8

无线、显示与物联网

60 h

目标：设备能显示、能联网、能被远程控制。

人机界面

  • LVGL 控件、样式、页面切换
  • 事件与回调机制
  • 触摸驱动与坐标校准
  • 界面刷新与性能

联网

  • BLE 广播 / 连接 / 特征值
  • WiFi 配网与断线重连
  • TCP / UDP 基础
  • MQTT 发布订阅与遗嘱
  • JSON 编解码
  • OTA 升级思路
验收：做一个带屏、能联网、手机可远程控制的设备；拔网线后能自动重连并上报状态。
M9

Linux 应用开发

80 h

目标：能在 Linux 上写一个真正可用的上位机或服务程序。

系统

  • 命令行、权限、进程管理
  • Shell 脚本
  • 系统调用：open/read/write/ioctl/mmap
  • pthread 线程与同步
  • socket：TCP / UDP / 串口

工程

  • CMake 与交叉编译
  • 日志分级
  • 配置文件解析
  • 守护进程与信号处理
  • gdb / strace / valgrind
验收：写一个 Linux 上位机：串口/网口控制板子，带配置、日志、异常重连，能连续跑 24 小时不崩。
M10

Linux 驱动开发

80 h

目标：能给一块自定义硬件写驱动，这是嵌入式 Linux 岗的分水岭。

能力

  • 内核模块编译与加载卸载
  • 字符设备：file_operations、read/write/ioctl
  • 设备树：节点、属性、compatible 匹配
  • platform 驱动模型、probe 流程
  • 中断处理：上半部 / 下半部
  • 并发与锁：自旋锁、互斥量、原子操作
  • 调试：printk、/proc、/sys、dmesg、oops 分析
  • GPIO / I2C / SPI 子系统
验收：写一个完整字符设备驱动，通过设备树匹配，支持 ioctl 控制；故意制造一次内核 oops 并独立定位到函数。
M11

电机控制与机器人方向

60 h

目标：把前面所有能力汇到一个"会动的"系统上，这是机器人岗的门票。

控制

  • 编码器测速
  • PID：位置 / 速度 / 电流环
  • 参数整定方法
  • FOC 基本原理
  • 死区、限幅、抗积分饱和

机器人

  • 坐标系与齐次变换
  • 正/逆运动学
  • 轨迹插补
  • 串口协议对接上位机
  • 简单视觉定位（可选）
验收：闭环控制一个电机，转速阶跃响应无超调或超调 < 10%；机械臂能按指令到达指定坐标，重复精度可测。

求职准备

60 h

目标：把三年做的事，变成别人愿意给你 offer 的证据。

硬准备

  • LeetCode 150 题
  • C 语言八股 100 问
  • 嵌入式八股：启动/中断/RTOS/时序
  • 项目复盘文档

软准备

  • 一页简历（STAR + 数字）
  • 三分钟讲项目
  • GitHub 项目首页
  • 模拟面试 ×3
验收：被陌生人问"你做过什么"，能在 3 分钟内让对方听懂并想追问；14 条能力自测全部能给出证据。
进阶方向 · 第三学年起 下面两块决定你走"嵌入式软件"还是"机器人算法"。至少深入一个，另一个知道边界就行—— 两块都只泛读，等于两块都不会。它们安排在核心模块之后，是因为都需要 M11 的运动学打底。
M13

具身智能与大模型控制

方向120 h

目标：让机械臂听懂一句话并抓到东西，而不是只在仿真里跑通。

原理

  • 三种范式：端到端 VLA / 分层指令 / 遥操作示教
  • 动作空间定义与归一化
  • 模仿学习：行为克隆、DAgger 与分布偏移
  • 强化学习：MDP、奖励设计、PPO 的直觉（不推公式）
  • sim2real gap 从哪来

实操

  • 遥操作采集 50 条抓放数据
  • 时间对齐、切分、数据增强
  • 行为克隆策略训练 + 仿真验证
  • LLM 解析"语言 → 子目标"（function calling / MCP）
  • 真机部署：推理延迟与控制频率
验收：说一句"把红色方块放到左边"，机械臂 10 次成功 ≥6 次；能讲清失败案例是数据不足还是分布偏移造成的。
M14

机器视觉与 SLAM

方向200 h

目标：给机器人装上眼睛，和"我在哪"。

视觉

  • C++ 核心：类、模板、STL、智能指针、CMake
  • 相机模型与标定（内参、畸变）
  • ORB 特征、匹配、对极几何、PnP
  • 点云：PCL、滤波、ICP 配准
  • 数学补丁：矩阵、概率、最小二乘

SLAM 与融合

  • 前端位姿估计、后端优化、回环检测
  • ORB-SLAM 的系统结构
  • 单目尺度为什么不可观
  • IMU 预积分、EKF / UKF
  • 松耦合 vs 紧耦合
验收：相机标定重投影误差 < 0.5 px；ORB-SLAM 跑通一段公开数据集并能逐段解释轨迹；自己写的 EKF 融合 IMU + 轮速，与真值对比。

三个递进项目

P1 证明你能做，P2 证明你能做好，P3 证明你能做难

P1 · 自画板数据采集终端

入门

自己画的小板 + 传感器采集 + OLED 显示 + 串口/Linux 上位机曲线。

时间 10 周 · 成本 ≈150 元
技术：M1–M5、M9
产出：板子 + 固件 + 上位机 + 测试记录

P2 · 无刷电机 FOC 驱动板

进阶

产出：转速波动可测、能演示低速平稳运行

P3 · 机械臂 / 竞赛系统

挑战

三轴机械臂 + 逆运动学 + 轨迹插补 + 视觉定位，或电赛获奖作品深化。

时间 14 周 · 成本 ≈400 元

产出：可重复演示的完整系统 + 复盘报告
