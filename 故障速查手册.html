故障速查手册

24 个高频故障：先查什么、常见根因、怎么验证。卡住的时候先来这里，比在群里问快得多。

A

编译、下载与启动

写代码之前先把程序跑起来
01下载器连不上（No target connected）▶

按顺序排查

  1. 换一根确认能传数据的 USB 线（很多线只能充电）
  2. 看设备管理器：下载器是否被识别、驱动是否装好
  3. 测目标板 3.3V 是否正常；下载器带不动板子时改用外部供电
  4. 查 SWD 四根线：SWDIO、SWCLK、GND、3.3V（VREF）
  5. 把 BOOT0 拉低后重新上电，再连
  6. 把 SWD 速率降到 1MHz 以下试
常见根因：杜邦线接触不良（占一半以上）、板子没供电、SWD 线序接反、芯片被读保护。
验证：用万用表测 SWDIO 对地电压，静止时应在 3.3V 左右；为 0 说明线断了或芯片没供电。
02烧录成功但程序不运行▶

按顺序排查

  1. 确认 BOOT0 = 0（从 Flash 启动）
  2. 确认复位脚没有被拉低（外部复位电路或按键卡住）
  3. 启动文件与芯片型号是否匹配（容量、系列）
  4. 时钟配置是否越界（超频、PLL 参数错）
  5. 用调试器全速运行，看 PC 停在哪里
常见根因：BOOT0 接错、启动文件拿错型号、时钟初始化死循环。
验证：先烧一个最简单的点灯工程。最简单的不跑，一定是环境问题，不是业务代码问题。
03HardFault 硬件错误▶

定位方法

  1. 在 HardFault_Handler 里打断点，停下来看 LR 与 PC
  2. 读栈帧：从 SP 取出 R0–R3、R12、LR、PC、xPSR，PC 就是出错指令地址
  3. 在反汇编窗口跳转到该地址，看是哪条指令
  4. 对照调用栈，找到出错的函数与行号

常见根因

  • 空指针 / 野指针解引用
  • 数组越界，踩坏栈或全局区
  • 未使能外设时钟就访问寄存器
  • 函数指针未初始化就调用
  • 栈溢出（中断嵌套太深、大数组放局部变量）
  • 非对齐访问（某些内核配置下）
验证：把大数组改成 static；打开栈溢出检测；逐步注释最近改的代码——HardFault 几乎总是最后一次改动引入的。
04程序反复复位 / 跑飞▶

按顺序排查

  1. 在 Reset_Handler 打断点，看是否真的在重启（会连续命中）
  2. 查看门狗：是否忘记喂狗、喂狗时间是否够
  3. 查电源：负载突变导致电压跌落触发 BOR
  4. 查复位脚：是否有干扰、上拉是否正确
  5. 查中断：是否进了未实现的中断（默认死循环）
常见根因：看门狗没喂、电源纹波太大、中断向量表缺项。
验证：上电后读复位标志寄存器（RCC_CSR），能直接告诉你是看门狗复位、掉电复位还是引脚复位。
B

电源与硬件

软件查不出来的时候，先量电压
05板子不亮 / 电压不对▶

按顺序测量

  1. 输入端电压（USB 5V 或电池）
  2. LDO 输入端与输出端
  3. 芯片每个 VDD 脚对地电压
  4. 断电测 VDD 与 GND 是否短路
常见根因：LDO 焊反或虚焊、输入端无电、去耦电容短路、PCB 上电源与地短路。
验证：限流电源（100mA）上电，正常空载电流通常几毫安；突然几百毫安就是短路。
06芯片发烫▶

按顺序排查

  1. 立刻断电，测电源对地电阻
  2. 查电源是否接反、LDO 是否过压输出
  3. 查 IO 是否直接驱动大电流负载（超过 20mA 就要加驱动）
  4. 查是否有引脚配置冲突导致两个输出对打
常见根因：电源反接、IO 灌电流、两个推挽输出短接。
验证：限流上电，摸温度同时看电流；手不要直接摸，用测温枪或先断电。
07晶振不起振▶

按顺序排查

  1. 确认用的是外部晶振模式，而不是内部 RC
  2. 负载电容是否按 C = 2×(CL − Cstray) 算对
  3. 晶振是否虚焊、贴反（无源晶振无方向，有源的要查）
  4. 用 MCO 引脚把时钟输出到管脚再测，避免探头电容影响
常见根因：负载电容差太多、焊接虚焊、晶振本身损坏。
验证：先把时钟切到内部 RC 看程序能否跑；能跑，说明问题就在晶振回路。
C

GPIO 与串口

最基础也最容易错的两块
08GPIO 没有输出▶

按顺序排查

  1. 外设时钟是否使能（GPIO 端口时钟最容易漏）
  2. 模式是否配成输出（默认是输入）
  3. 如果是复用引脚，是否配了复用功能号
  4. 引脚是否被别的外设占用
  5. 开漏输出必须外接上拉，否则量不到高电平
常见根因：忘记开端口时钟、复用号填错、开漏没上拉。
验证：直接写 BSRR / BRR 寄存器绕过 HAL；还不动就是硬件或配置问题，与库无关。
09串口乱码▶

按顺序排查

  1. 波特率是否两边一致（重点：系统时钟改了但波特率没跟着改）
  2. 数据位 / 停止位 / 校验位是否一致
  3. 电平是否匹配（3.3V 与 5V、RS232 与 TTL 不要混）
  4. 是否共地（不共地必乱码）
常见根因：时钟树配置改了，USART 的实际波特率算错；TIM 或 PLL 参数错误导致外设时钟不对。
验证：逻辑分析仪测一个位的宽度 T；波特率 = 1/T。和设置值一比就知道差多少。
10串口收不到数据▶

按顺序排查

  1. TX/RX 是否交叉连接（自己发自己收要短接 TX-RX）
  2. 接收中断是否使能、NVIC 是否打开
  3. 引脚是否配成复用而不是普通 GPIO
  4. 如果用 DMA，DMA 通道与传输长度是否对
常见根因：TXRX 接反、引脚复用没配、中断没开。
验证：先做回环测试（TX 短接到 RX），能收到说明 MCU 侧没问题，问题在线路或对端。
11串口偶尔丢数据▶

按顺序排查

  1. 接收缓冲是否够大（高速率下 256 字节起步）
  2. 中断优先级是否被更高优先级长时间抢占
  3. 中断里是否做了耗时操作（打印、延时）
  4. 是否只处理了"接收完成"而没处理"半传输/溢出"
常见根因：用轮询 + 长延时导致缓冲溢出；中断服务里调 printf。
验证：开溢出错误标志（ORE），一旦置位说明确实丢过数据。
D

I2C 与 SPI

总线问题，逻辑分析仪是唯一答案
12I2C 从机不应答（NACK）▶

按顺序排查

  1. 地址是否正确——注意 7 位地址与 8 位写地址差一位左移
  2. SDA/SCL 上拉电阻是否存在（4.7k 起步）
  3. 从机是否供电、是否在复位状态
  4. 速率是否超过从机支持（先用 100kHz）
  5. 总线是否被拉死（SDA 一直被拉低）
常见根因：地址写错（把 0x38 写成 0x70）、上拉缺失、从机没上电。
验证：逻辑分析仪看第一个字节，是 7 位地址左移一位加读写位；对照手册确认。
13I2C 偶尔通信失败▶

按顺序排查

  1. 上拉是否偏大（10k 以上在高速下上升沿变缓）
  2. 线是否太长、是否有干扰源（电机、开关电源）
  3. 是否有总线恢复机制（失败后发 9 个时钟 + STOP）
  4. 从机是否在做内部转换（需要等待，读太快会 NACK）
常见根因：传感器转换期间被读、没有超时与重试、上拉电阻过大。
验证：抓失败那一次的波形，重点看 ACK 位和第 9 个时钟。
14SPI 读回全 0x00 或全 0xFF▶

按顺序排查

  1. CPOL/CPHA 四种模式是否与从机一致（最常见）
  2. 片选 CS 是否在传输期间保持低电平
  3. MISO 是否接对、是否被其他器件拉低
  4. 时钟是否太快（先降到 1MHz 试）
  5. 从机是否需要上电延时或软复位
常见根因：SPI 模式选错；片选由 GPIO 控制但代码里没拉低。
验证：逻辑分析仪同时抓 SCK、MOSI、MISO、CS 四根线，能直接看出采样沿对不对。
15SPI 数据错位一位▶

按顺序排查

  1. 位序是 MSB first 还是 LSB first
  2. 数据帧长度 8 位还是 16 位
  3. DMA 传输宽度与地址对齐
常见根因：位序配反，值看起来像"除以 2 或乘以 2"。
验证：发一个已知字节 0x01，看波形上是最高位先出还是最低位先出。
E

ADC、定时器与 DMA

数据不对，先怀疑配置
16ADC 读数一直跳▶

按顺序排查

  1. 采样时间是否太短（高阻抗信号源要加长）
  2. 参考电压是否稳定（VDDA 上的噪声会直接进结果）
  3. 地线是否干净（数字地与模拟地）
  4. 输入阻抗是否过高，考虑加跟随器
  5. 是否加了滤波（滑动平均 / 中值）
常见根因：采样时间不够；被测信号本身有噪声。
验证：把输入端直接接地，看读数是否稳定在 0 附近。稳定说明是信号问题，不稳是 ADC 配置问题。
17ADC 读数固定不变▶

按顺序排查

  1. 通道号是否选对（引脚与通道的对应关系查手册）
  2. 引脚是否配成模拟模式（不能是数字输入）
  3. 是否只启动了一次转换，之后没再触发
  4. DMA 模式下是否只搬了一次
常见根因：通道填错、引脚没配模拟模式。
验证：换一个已知通道（比如内部温度传感器或 VREFINT）读一下，能变说明 ADC 本身正常。
18PWM 没有输出▶

按顺序排查

  1. 定时器时钟是否使能
  2. 对应通道是否使能输出（CCxE）
  3. 比较值是否落在 0 到 ARR 之间
  4. 引脚是否配成复用推挽
  5. 是否用了互补输出但主输出没开
常见根因：只配了定时器没开通道输出；比较值大于 ARR 导致恒为低。
验证：用逻辑分析仪看引脚，同时打印 CNT 与 CCR 的值。
19DMA 不搬运▶

按顺序排查

  1. DMA 控制器时钟是否使能
  2. 通道与外设的对应关系是否选对（每个外设固定通道）
  3. 传输长度是否大于 0（写 0 就是不动）
  4. 源/目的地址是否自增配置正确
  5. 外设是否真的产生了 DMA 请求（比如串口要先使能 DMA 发送）
常见根因：通道选错；外设侧没开 DMA 请求；长度写成 0。
验证：看 DMA 的传输计数寄存器（NDTR）是否在减少；不动就是根本没启动。
F

中断与 RTOS

时序问题最难查，先确认"有没有进"
20中断不进▶

按顺序排查

  1. 外设级中断使能位是否打开（比如 USART_CR1 的 RXNEIE）
  2. NVIC 里对应的 IRQ 是否使能
  3. 优先级分组与优先级数值是否合理
  4. 中断函数名是否与启动文件里的向量名完全一致
  5. 全局中断是否被关掉（__disable_irq 之后忘了开）
常见根因：函数名拼错导致进了默认死循环；忘了 NVIC 使能；临界区里出不来。
验证：在中断函数第一行翻转一个 GPIO，用逻辑分析仪看有没有跳变——比打断点可靠。
21中断只进一次 / 一直进▶

按顺序排查

  1. 中断标志是否清除（只进一次 = 标志没清）
  2. 是否清错了标志（清除时机不对导致丢失）
  3. 一直进 = 标志清得不够早，或者触发电平一直有效
  4. 中断里是否调用了会阻塞的函数
常见根因：标志位没清；边沿/电平触发选错。
验证：在中断入口计数并在主循环打印；计数不涨说明没进，涨得飞快说明标志没清。
22RTOS 任务不调度▶

按顺序排查

  1. 是否调用了启动调度器（vTaskStartScheduler）
  2. 任务栈是否太小（太小会直接 HardFault 或卡死）
  3. 任务里是否有死循环且没有阻塞（同优先级会被饿死）
  4. 是否在中断里调用了非 FromISR 版本的 API
  5. 中断优先级是否超过 configMAX_SYSCALL_INTERRUPT_PRIORITY
常见根因：中断优先级配置超过内核允许范围（这是最隐蔽的一个）。
验证：用 uxTaskGetStackHighWaterMark 查剩余栈；用调试器看当前在跑哪个任务。
23任务卡死不响应 / 死锁▶

按顺序排查

  1. 是否有两个任务以相反顺序获取同一组互斥量
  2. 是否在中断里拿互斥量（中断不能阻塞）
  3. 是否拿了锁之后提前 return 忘记释放
  4. 队列是否满了导致发送阻塞
常见根因：加锁顺序不一致；异常分支没解锁。
验证：暂停调试器看每个任务的调用栈，都停在获取锁上就是死锁。
24高优先级任务反而更慢（优先级反转）▶

现象

高优先级任务等一个被低优先级任务持有的资源，而中优先级任务抢占了低优先级任务，导致高优先级任务被"间接"拖延。

解决

  1. 用互斥量（带优先级继承）而不是二值信号量做互斥
  2. 缩短持锁时间，临界区里不做事
  3. 必要时用优先级天花板协议
验证：人为构造三个任务复现一次，观察持锁任务的优先级是否被临时提升。
G

通用排查法

什么现象都对不上时，用这套流程

六步定位法

1缩小范围：先确认是硬件、驱动还是业务。办法是烧一个最小工程——最小工程都不跑，问题在硬件或环境。
2把"看不见"变"看得见"：在关键位置翻转 GPIO，用逻辑分析仪看时序。比 printf 可靠，比打断点快。
3二分法：注释掉一半代码，看问题还在不在。反复二分，比逐行看快十倍。
4对照手册：不要凭记忆配寄存器。打开 Reference Manual 对应的那一节，逐位核对。
5查最后一次改动：90% 的新问题来自最近十分钟改的那几行。
6记录：把"现象 → 判断 → 试过什么 → 结论"写进周报。下次遇到同类问题，你有答案。
